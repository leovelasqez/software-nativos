# POS v1 — incremento 3

> Contexto histórico de incrementos 0–5. Para cambios nuevos prevalecen DEC-021 y specs/012-unified-web: un sitio único con Caja offline en navegador. Se conservan reglas y contratos comerciales.
Central: pos-api-v1.json. Payload: pos-payload-v1.schema.json. Snapshot: pos-snapshot-v1.schema.json. Envoltura/acuse sync-v1 intacta. HTTP central usa Host/Origin/X-Nativos-Request de fundamentos. Enrolamiento requiere sesión de dueño con settings.manage; token de instalación autenticado por X-POS-Token para authorize/sync. authorize admite sesión online o concesión anterior íntegra vigente y revalida usuario/permisos actuales. Clave pública fijada al enrolar. Sin emisión automática ante timeout/rechazo.

Firma Ed25519 sobre bytes UTF-8 exactos de document, JSON con grant/principal/actorName. Grant = offline-grant-v1; siete días. Firma y hash se verifican antes de operar. Snapshot central completo en una transacción; API pública no incluye costos. Venta referencia snapshotId y líneas {id,productId,snapshotId,quantity,optionIds}. El servidor reconstruye precios/impuestos/receta/consumos a partir del snapshot persistido: cliente no envía totales autoritativos. Mantener snapshots referenciados por historia. Cada línea fija su versión al agregarla; un alta online permite nuevas líneas con otro snapshot sin cambiar las anteriores. El ID es hash del contenido público y secuencia; descargar contenido idéntico reutiliza la versión. `cash.movement` está definido en `cash-movements-v1.md`: requiere conexión antes de crear el evento, pero conserva su orden e idempotencia en la misma cadena del turno.

Payload kind shift.open, sale.charge, shift.close; occurredAtMs, shiftId y datos específicos. Apertura base; venta orderId/snapshotId/lines/payment(method,received); cierre counted. Secuencia global por instalación, previousOperationId encadenado. Acuse accepted devuelve toda envoltura después de commit y reviewRequired si actor fue revocado desde concesión. Dispositivo revocado 403 conserva outbox. Predecesor pendiente 409 retry; conflicto hash/contenido/identidad 409 conciliación. Unicidad operationId/device+sequence/orderId. Consultas centrales de ventas requieren data.read + scope; paginación por ID ascendente en páginas de 50, cursor after/nextCursor. Lista local: últimos 50 comprobantes.

SQLite: versión/checksum y vinculación a installationId; snapshot y borrador completos; venta/recibo/consumos/caja/outbox en una transacción. Comandos locales tienen operationId, comparación de payload y respuesta persistida. Reintentos no vuelven a cobrar; pedido cobrado no vuelve a edición. Lista local muestra pendientes/errores/última actualización; saldo = snapshot base más efectos locales posteriores a serverSequence. Recarga de catálogo solo después de enviar cola anterior; fallo de descarga conserva la versión local.

Tokens, verificadores scrypt, concesiones firmadas históricas y reloj persistido se guardan en un archivo DPAPI exclusivo del usuario Windows, escrito y vaciado a disco antes del commit de venta. Outbox SQLite guarda solo grantId; no contiene firmas ni costos.

API local en loopback con Host/Origin estrictos, X-Nativos-Request y cookie HttpOnly SameSite=Strict aleatoria por login. GET /api/pos-local/status, POST /login, /enroll, /logout, /sync, PUT /order, POST /shift/open, /charge, /shift/close; GET /state y /receipt/:id. POST /api/products reutiliza el contrato central y exige la sesión online vigente del usuario; estado incluye snapshots públicos de las líneas y último cierre. Login {login,password}; enrolar {deviceId}. Comandos {operationId,...}; pedido {order} con revision optimista; charge {operationId,orderId,revision,payment}; apertura {operationId,openingCash}; cierre {operationId,counted}. Cuerpos cerrados/validación, límites y errores locales 400/401/403/429; central conserva sus códigos contractuales; ninguna respuesta devuelve token/grant firmado/verificador ni acceso SQL. Estado público contiene usuario/local/catálogo/pedido/turno/saldos/recibos/cola; la única identidad permitida es Consumidor final en esta versión.

Dinero/cantidades exactos a seis decimales. Precios incluyen impuesto asignado; null no calcula impuesto. Medio peso total hacia arriba; ajuste visible separado. Digital exacto, efectivo >=total y cambio. Consumos previstos multiplican cantidad vendida por receta congelada. No se bloquea saldo negativo: se alerta local/central. Impresión/copia posterior no altera venta; impresión física no validada aquí.
